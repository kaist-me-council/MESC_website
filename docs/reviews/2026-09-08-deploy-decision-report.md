## 3. 프로덕션에 미치는 영향

- **DB**: 마이그레이션 8개가 빌드 때 자동 적용. 전부 `CREATE TABLE`/`ADD COLUMN`/`DROP TABLE IF EXISTS PriorPurchase`(프로덕션엔 애초에 없던 표). 기존 표의 행은 건드리지 않음. `20260907000001_catchup_drift` 는 이미 있는 컬럼이면 건너뜀(로컬 빌드 스크립트가 "already exists" 를 skip).
- **기존 화면**: 홈 카드 추가, 대시보드 정리. 공지·자료·구성원 등 나머지는 그대로.
- **롤백**: Vercel 에서 이전 배포로 되돌리면 화면은 즉시 복구. 추가된 표·컬럼은 남지만 무해.
- **다른 브랜치와 충돌**: 다른 세션이 `style/home-first-impression` 에서 `components/home-client.tsx` 를 고치는 중. 이 브랜치도 그 파일에 카드 1개를 넣었으므로 두 브랜치를 합칠 때 그 파일만 수동 병합 필요. **이 브랜치를 먼저 병합하는 것을 권장**(충돌 범위가 작음).

## 4. 배포 후 필수 3단계 (메일 전)

1. 프로덕션 관리자 → 이벤트 신청·구매 → **"상반기 반팔티(수령 확인용) 만들기"** 버튼.
2. 만들어진 캠페인 → 신청 목록 탭 → **주문 적재** → 모드 "배부 시트" → `~/Downloads/반팔티_나눠주기_import.csv` 선택 → 미리보기(146명, 문제 0건이어야 함) → 적재. 적재 후 CSV 파일 삭제.
3. `/shop/check` 를 폰으로 열어 **본인 이름+학번**으로 조회 → 주문 내역 확인 → 응답 제출 → 관리자 목록에 반영 확인.

그다음 메일 발송(초안: `docs/superpowers/specs/2026-09-07-tshirt-shop-design.md` 8절). 회신 마감 9/13.

## 6. 코드 리뷰 결과

`/code-review 1 high` 를 돌렸으나 세션 한도(9시 초기화)로 오케스트레이터와 정확성 관점 3개(누락 동작·교차 파일 추적·상위 설계)가 중간에 끊겼고, 품질 관점 4개(재사용·컨벤션·효율·단순화)는 완료됐습니다. 끊긴 정확성 부분은 제가 직접 핵심 경로를 읽어 대신 확인했습니다.

**정확성 (직접 검토, 배포 차단 없음)**
- 일괄 상태 변경 `PUT {orderIds}` 는 `campaignId` 로 범위를 제한해 다른 캠페인 주문을 못 건드림 ✓
- 본인 취소·수령 확인·주문번호 조회는 모두 해당 캠페인 안에서만 매칭 ✓. 취소는 pending 만, 확인은 캠페인 공개+확인 켜짐+마감 전만 ✓
- 적재 교체는 `source="import"` 주문만 삭제(웹 신청 보존), 미리보기에서 삭제 건수·응답 건수 경고 ✓
- 재고 검사는 트랜잭션 없음 — 소량 캠페인에서 실질 위험 낮음. 초과 판매가 실제로 나면 그때 `$transaction` (코드에 ponytail 주석)

**효율 (1건 바로 반영, 나머지 후속)**
- 반영: 재고 제한 옵션이 없는 캠페인은 공개 조회 때 주문 전체 스캔을 건너뜀(반팔티 수령 확인 캠페인이 이 경우).
- 후속: 관리자 캠페인 목록이 집계를 위해 주문 행을 다 가져옴(캠페인 수·주문 수가 커지면 groupBy 로), 공개 페이지를 ISR 서버 컴포넌트로(현재는 방문마다 API 호출. 146명 메일 규모에선 문제 없음).

**재사용·단순화 (후속 PR, 동작 영향 없음)**
- 상태/선택 한글 라벨·구분 목록이 서버·공개·관리자에 3~4벌 중복 → 클라이언트 안전 공용 모듈로 통합.
- `noStore`·JSON 파싱·레이트리밋 서두가 라우트 10곳에 반복 → 작은 헬퍼로.
- 관리자 화면이 API 응답을 방어적으로 재정규화하는 코드, 안 쓰는 응답 필드(preview·optionCount), 같은 PR 안에서 생성됐다 삭제된 PriorPurchase 마이그레이션 → 정리.
- 이중언어 선택을 `lib/bilingual.ts` `pick()` 으로 통일.

**컨벤션 (후속, 시각적 사소)**
- 관리자 뱃지에 팔레트 원색(emerald/amber) 직접 사용 → `badge-success` 등 유틸로. 이미지 순서 버튼 ←/→ 글자 → lucide 아이콘. 구분 `<select>` → shadcn Select. 갤러리 aria-label 한국어 고정 2곳.

판정: 위 어느 항목도 데이터 손상·보안·9/8 메일 흐름과 무관. 배포 판단을 바꾸지 않습니다.

## 8. "정보가 날아가거나 서버가 죽으면?" — 상황별 실제 동작 (코드·설정으로 확인)

| 상황 | 무슨 일이 생기나 | 근거 |
|---|---|---|
| 학생이 신청 버튼을 눌렀는데 화면이 안 넘어감 | 저장은 응답 전에 DB에 먼저 끝남. 주문번호가 화면에 안 떠도 "내 신청 확인"에서 이름+학번/이메일로 다시 찾을 수 있음 | `orders/route.ts` create → 201 |
